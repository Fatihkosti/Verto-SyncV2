# تقرير فشل مزامنة Verto عبر ADB/Logcat

## النتيجة المثبتة

إصدار Release سجّل فشل مهمة WorkManager الخاصة بالمزامنة، لكنه لم يسجّل الاستثناء الذي أدى إلى الفشل. لذلك لا يمكن تحديد السبب الجذري الأصلي من هذه المحاولة دون تخمين.

## السياق الزمني

- بدأ التسجيل: `2026-09-09 21:04:55` تقريبًا، دون مسح Logcat السابق.
- قبل التنفيذ: الشبكة كانت `isConnected=true` و`isValidated=true` عند `21:05:53.659`.
- بدء المهمة: `21:05:53.665` — `WM-WorkerWrapper: Starting work for com.verto.app.data.sync.SyncWorker`.
- نتيجة المهمة: `21:05:57.916` — `WM-WorkerWrapper: Worker result FAILURE`.
- المدة بين بدء المهمة والفشل: نحو `4.251` ثوانٍ.
- انتهى التسجيل بعد تأكيد ظهور الفشل.

## الأدلة المسجلة

- WorkManager بدأ `SyncWorker` مرة واحدة.
- WorkManager أعلن `Worker result FAILURE` مرة واحدة.
- لم يظهر في نافذة المحاولة أي `FATAL EXCEPTION` أو `AndroidRuntime`.
- لم يظهر `Caused by` مرتبط بتطبيق Verto؛ ظهر سطر `Caused by` واحد خاص بخدمة Bluetooth في النظام وغير مرتبط بالمزامنة.
- لم تظهر رسائل `SyncManager` أو `Room` أو `Supabase` في نافذة الفشل.
- لم يظهر stack trace أو HTTP status/response أو رسالة قاعدة بيانات تخص Verto.

## السبب

السبب المثبت بالأدلة هو: فشل `SyncWorker` أثناء تنفيذ مهمة المزامنة، مع إرجاع WorkManager للحالة `FAILURE`.

السبب الداخلي الدقيق غير مسجل في Release. الكود الحالي يمسك الاستثناء داخل `SyncWorker` ويحوّله عبر سياسة التصنيف إلى `Result.failure()` دون تسجيل الاستثناء الكامل، كما أن مسار `SyncManager` لا يرسل stack trace إلى Logcat في هذه الحالة.

## الملفات

- السجل الخام محفوظ محليًا هنا: `verto-sync-20260909-210455.raw.log`.
- النسخة المنقحة من السجل: `verto-sync-20260909-210455.sanitized.log`.
- تم تنقيح JWT والتوكنات والبريد الإلكتروني ومعرّفات UUID والأرقام الطويلة قبل مشاركة النسخة المنقحة.

## القيود والإجراءات

- لم يتم مسح Logcat السابق.
- لم يتم مسح بيانات التطبيق أو تسجيل الخروج أو إعادة التثبيت.
- لم يتم تغيير كود المشروع أو إعداداته.
- يلزم إصدار Debug/تشخيصي يسجل `Throwable` كاملًا، أو إصلاح logging في Release، لتحديد الاستثناء وسلسلة `Caused by` في محاولة لاحقة.
