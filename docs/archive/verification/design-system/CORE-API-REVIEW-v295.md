## Session 295 decisions

- `VertoListRow`: `ADOPT_CANDIDATE`; its nullable `onClick` contract was corrected without changing its signature or layout. It remains unused by production call sites in v294/v295 and is not removed in this session.
- `VertoPermissionPrompt`: its resource-backed default was fixed; it has zero production consumers and is only classified for possible removal in 302. `VertoConfirmationDialog`: its dismiss default was resource-backed and it remains actively consumed by `feature/shipment` (3 call sites).
- `VertoErrorState` / `VertoOfflineState`: only ownership of their default state labels changed to Core resources; API and copy are unchanged.
- No public API was renamed, moved, internalized or deleted in 295.

## Test infrastructure finding

`core/designsystem` has only `src/test` and declares `testImplementation(libs.junit)`. It does not declare Compose UI test dependencies. A behavior-level `performClick()`/semantics test would require a Gradle dependency or a new Android test setup, both forbidden by the session contract; therefore the required interaction tests cannot be added honestly in 295 under the current source constraints.
